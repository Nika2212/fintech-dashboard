## 2. Рекомендуемая архитектура

```text
Angular UI
  ├── DashboardComponent
  ├── Settings
  └── Router
        │
        ▼
MarketDataFacade
  ├── Состояние приложения
  ├── Управление запусками
  ├── Настройки
  └── Pause / Resume
        │
        ▼
Web Worker
  ├── Инициализация Wasm
  ├── Планирование пакетов
  └── Протокол сообщений
        │
        ▼
AssemblyScript → WebAssembly
  ├── Генерация случайных значений
  ├── Эволюция цен
  └── Состояние инструментов
        │
        ▼
Metric Aggregator (TypeScript)
  ├── Last traded price
  ├── Bid–ask spread
  ├── Cumulative volume
  ├── VWAP
  └── Order-book imbalance
```

### Архитектурные решения
- Генерацию случайных значений и изменение цен выполнять внутри Wasm.
- Метрики рассчитывать на TypeScript, например внутри Worker: это упрощает тестирование.
- Состояние активного запуска хранить в сервисе уровня приложения, а не в компоненте страницы.
- Каждое сообщение Worker должно содержать `runId`.
- UI можно обновлять реже, но каждая сделка должна учитываться в агрегатах.

## 4. Метрики и формулы

| Метрика | Формула | Правило |
|---|---|---|
| Last traded price | Цена последней сделки | Обновляется при каждой сделке |
| Bid–ask spread | `askPrice - bidPrice` | По последнему снимку bid/ask |
| Trading volume | `Σ tradeQuantity` | С начала текущего запуска |
| VWAP | `Σ(price × quantity) / Σ(quantity)` | Накопительно с начала запуска |
| Order-book imbalance | `(bidQuantity - askQuantity) / (bidQuantity + askQuantity)` | Диапазон от -1 до +1 |

### Правила расчётов
- Генерируемые цены хранить в целых центах.
- Для VWAP хранить накопленные `price × quantity` и `quantity`, а не историю сделок.
- Если знаменатель равен нулю, отображать недоступное значение.
- Каждую сделку учитывать ровно один раз.
- Bid/ask quantities не добавлять к торговому объёму.
- Форматировать цены как валюту только при отображении.

### Контрольный пример
Две сделки:
- 10 единиц по $100.
- 30 единиц по $102.

Ожидаемые результаты:
- Last traded price: `$102.00`
- Volume: `40`
- VWAP: `$101.50`

При bid `$101.96` и ask `$102.00` спред равен `$0.04`. При bid quantity `600` и ask quantity `400` imbalance равен `0.20`.

## 5. Настройки генератора

| Параметр | Значение по умолчанию | Допустимый диапазон |
|---|---:|---:|
| Instrument count | 5 | 1–50 |
| Updates per batch | 100 | 1–1 000 |
| Batch interval | 500 мс | 50–2 000 мс |

Все значения должны быть целыми числами.

Пример: 100 обновлений каждые 500 мс — номинально 200 обновлений в секунду суммарно по всем инструментам, а не на каждый инструмент.

Изменение полей формы не должно влиять на активный генератор до нажатия **Apply**. После Apply создаётся новый запуск и сбрасываются предыдущие значения и агрегаты.

## 6. Критические сценарии

### Pause / Resume
- Pause останавливает генерацию.
- Resume продолжает тот же запуск.
- Накопленные метрики сохраняются.
- За время паузы не создаются дополнительные сделки.

### Apply Settings
- Проверить настройки.
- Остановить или инвалидировать предыдущий запуск.
- Сбросить метрики и агрегаты.
- Запустить генерацию с новыми настройками.
- Новый запуск должен стартовать даже тогда, когда предыдущий был на паузе.

### Навигация
- Переход между DashboardComponent и Settings не должен сбрасывать данные.
- Навигация не должна создавать дополнительные генераторы.

### Защита от старых сообщений
- Каждому запуску назначается уникальный `runId`.
- Результаты от предыдущего `runId` игнорируются.
- Повторное применение настроек не должно позволять старым данным перезаписать новое состояние.

### Производительность
- Обрабатывать все сделки для точных метрик.
- Не хранить полную историю событий.
- При необходимости ограничивать частоту обновления интерфейса, а не расчётов.

## 7. Обязательные unit-тесты

| Область | Что проверить |
|---|---|
| Metric calculations | Пример из задания, нулевые знаменатели, несколько инструментов |
| Settings validation | Значения по умолчанию, границы, дробные и недопустимые значения |
| Apply/reset | До Apply настройки не влияют на генератор; после Apply метрики сбрасываются |
| Pause/resume | Пауза останавливает генерацию, Resume сохраняет накопленные значения |
| Run lifecycle | Результаты старого `runId` игнорируются |
| Wasm generator | Размер пакета, положительные цены и количества, корректные bid/ask |
| Worker lifecycle | Ошибки инициализации и освобождение ресурсов |

По возможности использовать контролируемые зависимости и тестовые часы, а не длительные реальные ожидания. End-to-end тесты не обязательны.
